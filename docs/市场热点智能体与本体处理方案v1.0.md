# 市场热点智能体与本体处理方案 v1.0

## 一、建设目标

面向东方航空营销人员，建设“市场热点采集—智能体分析—本体沉淀—机会洞察”的生产链路。平台不把每条新闻直接当作营销机会，而是先将外部热点作为可追溯的市场证据，经业务相关性判断、对象抽取、关系校验和人工门禁后，再形成市场信号、市场、航线、航班、客户需求和营销机会等业务对象。

核心链路：

```text
RSS / Atom / JSON API / 数据库 / 手工导入
→ 归一化与去重
→ 主题、相关性、趋势和风险判断
→ 市场热点处理智能体抽取对象与关系
→ 本体准入校验
→ 人工确认或驳回
→ 更新营销本体
→ 机会洞察智能体形成机会候选
→ 营销人员选择客群、产品包和活动方案
```

## 二、参考工程的借鉴

### 1. deepseek-harness

借鉴插件化 Harness、统一 Agent Loop、工具调用、运行状态和事件追踪机制。热点处理过程中的每一个阶段都保留事件，包括标准化、分类、模型调用、模型失败回退、准入判断和本体更新，便于运营人员查看“智能体做了什么、依据是什么、最终写入了什么”。

借鉴人工审批门禁和失败治理思路：大模型只提供建议，最终本体写入需要人工确认；模型超时、返回非法 JSON 或供应商不可用时，系统使用规则结果继续处理，不让单条热点拖垮整批任务。

### 2. ai-news-radar

借鉴多来源 RSS / Atom 采集、官方来源优先、来源健康检查、标题与 URL 去重、内容标准化、主题分类、相关性评分、摘要和排序方法。平台将这些方法适配到航空营销业务，增加航线、航班、客座率、运价、空铁联运、旅游目的地、商务差旅、会员、卡券和辅营产品等业务词汇与对象。

## 三、热点数据接入

平台支持以下来源类型：

- RSS / Atom：新闻媒体、行业协会、机场或目的地官方信息。
- JSON API：搜索趋势、市场热度、旅游平台、舆情服务等接口。
- 数据库或数据仓库：航班经营、客座率、运价、渠道、会员和活动反馈数据。
- 手工导入：运营人员临时上传的结构化热点或调研结果。
- 后续扩展：小红书、抖音等外部热点接口，前提是符合数据授权和合规要求。

所有热点保留来源名称、来源地址、来源类型、原始标题、原始内容、发布时间、采集时间、内容哈希和去重键。不同租户之间按 `tenant_id` 隔离，重复数据不会重复进入处理队列。

## 四、热点处理智能体

市场热点处理智能体使用统一 Harness 执行，先采用确定性规则提供基础判断，再调用租户配置的大模型进行补充分析。模型输出只允许覆盖受控字段，系统会对分数、对象类型、关系类型、标识、证据和字段长度进行二次清洗。

智能体主要工作：

1. **内容归一化**：清理 HTML、空白字符、追踪参数和无效链接。
2. **热点去重**：优先使用规范化 URL；没有 URL 时使用来源和标题组合去重。
3. **业务相关性判断**：识别是否涉及东航可经营的航线、航班、市场、旅客需求、机票、会员、卡券或辅营产品。
4. **主题分类**：区分节假日出行、旅游目的地、商务差旅、航班经营、价格促销、会员与辅营等主题。
5. **趋势判断**：结合主题数量、航空关键词密度和模型判断生成趋势分，用于排序，不直接决定正式机会。
6. **业务对象抽取**：抽取 `MarketSignal`、`Market` 等对象；有充分证据时再扩展到 `Route`、`Flight`、`CustomerNeed` 等对象。
7. **关系抽取**：识别市场信号关注的市场、航线、航班或需求，并校验关系端点类型。
8. **机会候选生成**：只生成候选，不自动创建正式营销机会；正式机会需经过本体确认和运营人员操作。

## 五、本体准入与人工门禁

热点进入知识中心不等于进入本体。系统使用以下准入条件：

- 对象类型必须是平台注册的业务对象类型。
- 必须有稳定的外部标识或系统生成的稳定标识。
- 必须有原始标题、内容摘要或来源链接作为证据。
- 置信度达到准入阈值。
- 关系两端必须存在，且符合语义模型中定义的端点类型。
- 不允许把个人旅客明细写入市场热点本体，只能使用聚合客群和匿名统计信息。

准入结果分为：

- **待确认本体**：智能体判断有明确业务对象和证据，等待营销人员确认。
- **仅知识保留**：内容有参考价值，但无法稳定映射到业务对象，保留在知识中心，不更新本体。
- **已驳回**：人工判断证据不足、业务关联不成立或不适合沉淀为本体。
- **本体已更新**：人工确认后写入对象和关系。

人工确认时记录操作人、时间、说明和更新对象数量，形成可审计的变更记录。

## 六、重点本体对象和关系

重点对象包括：

```text
MarketSignal       市场信号
Market              市场或目的地
Airport             机场
Route               航线
Flight              航班
MetricObservation   经营指标观测
CustomerNeed        客户需求
CustomerAggregate   聚合客户
AudienceSnapshot    客群快照
Opportunity         营销机会
ProductPackage      活动产品包
Campaign            营销活动
Evidence            外部证据
Feedback            触达与交易反馈
Review              复盘记录
Recommendation      优化建议
```

热点处理阶段使用的核心关系：

```text
MarketSignal → derived_from → Evidence
MarketSignal → concerns_market → Market
MarketSignal → concerns_route → Route
MarketSignal → concerns_flight → Flight
MarketSignal → reveals_need → CustomerNeed
MarketSignal → identifies → Opportunity
Opportunity → has_evidence → Evidence
Opportunity → targets_audience → AudienceSnapshot
Opportunity → addresses_opportunity → ProductPackage
Campaign → addresses_opportunity → Opportunity
```

其中 `MarketSignal → concerns_market → Market` 用于表达“热点信号关注哪个市场”，而不是简单地把新闻标题当作市场对象。

## 七、热点到机会洞察

机会洞察智能体读取已确认的市场信号、本体市场、航线经营指标、聚合客群和可售产品包，形成可执行的机会建议。例如：

- 旅游目的地热度上升 + 上海至三亚搜索增长 + 航线未来 15 天运力充足：建议评估早鸟机票、行李、优选座位或目的地卡券组合。
- 国际展会热度上升 + 京沪商务客群返程未购 + 公务舱库存可售：建议评估商务差旅返程提醒和升舱权益。
- 空铁联运讨论度上升 + 机场中转衔接符合 MCT：建议评估空铁联运、远程值机和中转服务组合。

机会洞察输出应包含市场范围、可能关联航线、需求解释、证据来源、推荐产品方向、预估影响和待人工确认项。系统不应把低相关性新闻直接转为营销活动。

## 八、前端工作台

市场热点工作台至少提供：

- 热点列表：来源、发布时间、主题、相关性、趋势分、风险等级和本体状态。
- 热点详情：原始内容、来源链接、智能体决策、候选对象、候选关系和机会候选。
- Agent 处理轨迹：按时间显示标准化、分类、抽取、准入和模型回退等事件。
- 人工门禁：确认更新本体、仅保留知识、重新处理。
- 机会动作：仅在本体更新完成且存在机会候选时，允许形成营销机会。
- 数据隔离：只显示当前租户的数据，不能跨租户查看热点、证据和本体对象。

## 九、失败与治理

- 来源不可达：记录来源失败和错误类型，不影响其他来源处理。
- XML 格式异常：单来源失败，保留任务状态和错误信息。
- 大模型调用失败：记录模型回退事件，使用规则结果完成处理。
- 模型输出非法：丢弃非法对象或关系，不直接写入本体。
- 关系端点错误：保留热点知识和拒绝原因，不创建关系。
- 重复导入：按租户和去重键识别，返回重复数量。
- 删除热点：删除该热点产生的本体对象、关联关系和热点记录；不删除其他来源共同引用的对象。

## 十、后续扩展

后续可增加市场热点来源配置表，统一管理来源启停、健康状态、采集周期、限流、最近错误和租户归属。还可以增加批量机会洞察接口：筛选高相关性、高趋势且经过本体确认的热点，结合 `Route`、`Flight`、`MetricObservation`、`AudienceSnapshot` 和 `ProductPackage` 生成机会候选，继续保留人工确认环节。

对于航班、用户、市场、经营和热点接口，建议统一经过数据处理智能体清洗、抽取和分级，再通过本体准入规则更新对象。用户数据只以聚合客群、画像快照或统计指标进入营销本体，避免写入个人旅客明细。
