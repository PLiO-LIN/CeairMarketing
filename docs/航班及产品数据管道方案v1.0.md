# 东航航班及产品数据管道方案 v1.0

## 1. 建设结论

参考 `竞赛/05_参考工程/爬取航班及产品数据` 可以建立航班及产品数据管道，但参考工程更适合作为“数据采集适配器”，不能直接作为生产入库程序。它通过 Selenium/Chrome CDP 监听东航查询页面接口，采集 `briefInfo`、`querySummaryPrice` 两类快照，再由 `json2db.py` 按产品标签、产品组、活动产品、辅营产品、航班、航段、舱位和运价顺序导入关系库。

平台已将这类快照接入统一数据处理流水线：

```text
爬虫或授权接口快照
  -> 原始批次留存
  -> 航班及产品标准化适配
  -> 数据质量与本体关系校验
  -> 数据处理智能体补充分析
  -> 人工二次确认
  -> 本体对象与关系更新
  -> 产品匹配、机会洞察、活动编排使用
```

## 2. 参考工程字段映射

| 参考数据 | 平台业务对象 | 主要用途 |
| --- | --- | --- |
| `productLabelInfoList` | 产品标签 `ProductLabel` | 描述灵活退改、行李、权益等产品属性，支持活动筛选与内容生成 |
| `productGroupInfoList` | 产品组 `ProductGroup` | 组织产品分组，支撑产品包和活动产品引用 |
| `productInfos` | 活动产品 `Product` | 记录产品编码、促销编码、适用人群、购买会员和使用方式 |
| `xProductMap` | 辅营产品 `AncillaryProduct` | 记录额外行李、选座、贵宾室、保险、Wi-Fi 等可选服务及价格 |
| `flightItems.flightInfos` | 航班 `Flight` | 支撑航班营销机会、库存/价格判断和活动定向 |
| `flightSegments` | 航段 `FlightSegment` | 支撑多航段、联程和中转关系分析 |
| `cabinInfoDescs` | 舱位 `Cabin` | 支撑舱等、舱位代码和可售层级判断 |
| `fareInfoDescList` | 运价 `Fare` | 支撑旅客类型、票价、税费、退改和产品引用 |
| `tripLabelIds` | 航班-产品标签关系 | 支撑航班标签筛选和产品匹配解释 |

## 3. 本体对象与关系

本次管道补充以下对象类型：

- `Airport`：机场代码、名称和机场业务属性。
- `Route`：出发机场、到达机场和航线市场。
- `Flight`：航班号、承运航司、运行日期和原始航班信息。
- `FlightSegment`：行程中的单个航段。
- `Cabin`：舱位代码、舱等和库存层级。
- `Fare`：旅客类型、基础票价、税费、总价、退改价和产品引用。
- `ProductLabel`：产品管理平台提供的可配置产品标签。
- `ProductGroup`：产品管理平台中的产品分组。
- `Product`：机票运价、联运、会员权益、卡券等营销产品。
- `AncillaryProduct`：额外行李、选座、贵宾室、保险、Wi-Fi 等辅营产品。

主要关系为：

```text
Route -> departs_from -> Airport
Route -> arrives_at -> Airport
Flight -> operates_on -> Route
Flight -> has_segment -> FlightSegment
Flight -> has_cabin -> Cabin
Cabin -> has_fare -> Fare
Fare -> uses_product -> Product / AncillaryProduct
Product -> belongs_to_product_group -> ProductGroup
Product -> has_product_label -> ProductLabel
Flight -> has_product_label -> ProductLabel
Fare -> includes_ancillary -> AncillaryProduct
```

每个对象都保留来源名称、采集接口、批次、原始字段、有效时间、置信度和处理任务编号。相同业务对象通过稳定标识合并，避免每次抓取都产生重复节点。

## 4. 数据处理智能体职责

航班及产品管道首先由确定性的适配器完成字段拆解和关系生成，数据处理智能体负责以下工作：

1. 检查必填字段、编码格式、价格类型和航段完整性。
2. 识别同一航班、舱位、运价或产品的重复快照，并标记版本变化。
3. 判断缺失机场、孤立运价、无对应产品编码、异常价格和不完整辅营引用。
4. 对可映射的对象补充业务分类、来源证据和有效期建议。
5. 对无法确认业务含义的数据保留在知识和处理结果中，不强行写入本体。
6. 输出对象候选、关系候选、质量问题、处理轨迹和本体准入结论。

智能体只提供候选和建议，不能绕过人工确认直接更新正式本体。对于由产品管理平台提供的稳定产品主数据，可通过受信任接口配置自动准入策略；对于网页采集、价格快照和新产品关系，默认需要人工二次确认。

## 5. 接口调用

新增专用接口：

```http
POST /api/data-pipelines/flight-products
```

请求示例：

```json
{
  "source_name": "东航官网航班及产品爬虫",
  "payload": {
    "data": {
      "productLabelInfoList": [],
      "productGroupInfoList": [],
      "productInfos": [],
      "xProductMap": {},
      "flightItems": []
    }
  },
  "require_confirmation": true
}
```

接口返回统一数据任务编号和处理阶段。典型阶段包括：

```text
received
normalizing
normalized
semantic-validation
semantic-validated
awaiting-confirmation
ontology-updated
```

人工确认仍使用统一接口：

```http
POST /api/data-pipelines/{job_id}/review
```

确认通过后才会创建或更新本体对象和关系；驳回时保留原始快照、知识记录和智能体处理轨迹，但不更新正式本体。

## 6. 对营销业务的支撑

产品匹配智能域可以根据航线、航班日期、舱位、运价、会员资格、产品标签和辅营价格，为客群生成可解释的产品包候选。例如，对近期搜索某航线且价格敏感的客户聚合，可匹配折扣运价；对已购买机票且存在行李需求的聚合客群，可匹配预付费行李；对中转航班，可结合航段和衔接时间筛选空铁联运或中转服务。

机会洞察智能域可以同时读取航班经营指标、航班价格、航线热度和市场热点，发现低客座率、提前售卖不足、重点航线价格波动或辅营销售机会，并将机会与具体航线、航班和产品建立关系。活动编排智能域据此生成活动版本、内容和触达批次，效果分析智能域再将出票、辅营购买、会员活跃和渠道反馈回流到活动及产品关系中。

## 7. 生产化建议

参考爬虫适合用于验证数据结构、建立样例和补充暂时缺少接口的数据，不建议长期直接依赖官网页面抓取。生产环境应优先采用东航内部产品管理平台、航班运行系统、收益管理系统和授权数据交换接口；爬虫作为补充来源时，需要设置访问频率、失败重试、快照版本、字段变更告警和人工审核。

建议按以下方式运行：

- 产品主数据：按产品管理平台发布事件或定时接口同步。
- 航班计划与运行数据：按日计划和实时运行接口同步。
- 运价与库存：按查询快照或授权接口增量同步，并保留有效时间。
- 辅营产品：与产品编码、资源编码和销售价格保持关联。
- 本体更新：所有新增关系记录来源、证据、置信度和审核人。
- 数据删除或失效：按批次和来源反向清理本体对象，保留审计记录。
