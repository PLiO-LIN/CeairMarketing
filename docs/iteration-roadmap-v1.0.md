# 后续迭代路线 v1.0

> 基于 2026-08-31 `main` 分支现状整理。本文作为后续开发的执行基线，优先保证真实航空营销业务闭环、数据可追溯和 AI 可治理。

## 当前基线

- 实际部署前端：`apps/web-v32`
- API：FastAPI + PostgreSQL
- 已有六个智能域、统一 Harness、知识中心、本体图谱、数据处理流水线、多租户和模型配置
- 已有活动、机会、客群标签、客群包、热点、知识文档、模型和 Agent Run 基础接口
- 当前验证：后端测试 24 passed，前端 JavaScript 检查通过

## P0：安全和发布基线

1. 轮换历史上曾进入本地配置或聊天记录的所有密钥。
2. `.env` 只保留在本地和服务器，不进入 Git；生产配置使用服务器环境变量或 GitHub Secrets。
3. 增加密钥扫描和依赖安全检查，阻止带凭据的提交。
4. 增加数据库迁移版本、备份、回滚和发布后健康检查。
5. 统一版本号、错误码、日志脱敏和审计字段。

## P1：营销活动主链路

围绕一条活动主记录串联：

```text
机会 -> 客群快照 -> 活动产品包 -> 内容版本 -> 活动 -> 审批 -> 执行批次 -> 渠道回执 -> 转化结果 -> 复盘结论
```

交付内容：

- 活动详情、版本、审批、执行、回执和复盘统一关联
- 活动状态机限制非法流转
- 产品包、客群包、机会、内容真实落库
- 活动详情支持查看全链路证据和 Agent 运行记录
- 删除、归档和回滚具备关系校验和审计记录

## P1：机会和客群生产化

机会支持航线、航班运行、国际地区、中转、空铁联运、会员权益、卡券、辅营、热点和 ToB 等类型，并保存数据源、评分依据、有效期和证据。

客群形成“画像指标/标签 -> 标签组合 -> 客群包/客群快照”三级结构，支持内部画像接口同步、AI 圈选、规模评估、标签关系和触达保护。

## P2：产品与内容服务化

产品管理平台向营销平台输出可引用产品包，覆盖客票运价、航线航班、空铁联运、会员权益、卡券和辅营服务。产品匹配智能域只生成候选和解释，产品事实以产品管理平台为准。

内容工坊支持 App、短信、微信、官网、小程序、企业客户等渠道版本，内容生成必须引用已审核产品事实，并保留人工编辑、审核和版本记录。

## P2：知识中心和本体治理

文档、接口和数据库数据经过解析、清洗、抽取、校验后形成候选对象。适合计算和关联的事实进入本体，不适合建模的内容只保留在知识库。每次本体变更经过人工确认，保留来源、证据、置信度、有效期和回滚记录。

## P3：六个智能域协同

- 机会洞察：发现趋势、异常和可经营机会
- 客群洞察：自然语言圈选、关系扩展、规模与保护评估
- 产品匹配：生成候选产品包并解释适配依据
- 活动编排：组合机会、客群、产品、内容、预算和渠道
- 内容生成：生成渠道版本并做事实与风险检查
- 效果分析：归因、异常发现、复盘和策略学习

所有智能域统一输出结果、依据、置信度、警告、拟写入对象、工具调用和 trace id；创建、审批、发布和本体写入保留人工确认。

## P3：生产运营和评估

补齐渠道回执、送达、点击、购票、卡券领取/核销、辅营购买、收入、退订、投诉和异常数据，形成活动级归因。建立 Agent 成功率、人工采纳率、建议准确率、节省时长、Token 用量和增量收入等指标。

## 迭代顺序

```text
安全治理 -> 活动主链路 -> 真实数据落库 -> 审批执行闭环
-> 机会/客群生产化 -> 产品匹配/内容生成 -> 知识与本体治理
-> 多智能体协同 -> 归因复盘与策略学习
```

## 验收原则

每次迭代必须同时具备业务验收、权限验收、数据溯源验收、异常处理验收和自动化测试，不以页面能展示作为唯一完成标准。
