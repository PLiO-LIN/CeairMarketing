# 营销活动闭环开发说明 v1.0

## 1. 建设范围

本版本将营销平台从“可展示的活动工作台”推进为“可持久化的活动闭环纵向切片”。范围覆盖活动创建、版本冻结、人工审批、受控执行、反馈导入、效果复盘和操作审计。

该版本用于本地原型验证和比赛演示。渠道执行与反馈数据仍是受控模拟或授权导入，不代表已经连接东航生产触点、交易、辅营或财务系统。

## 2. 状态机

```text
草稿 / 退回修改
  -> 提交审批
  -> 待产品确认
  -> 待营销审批
  -> 待合规复核
  -> 已批准
  -> 待执行
  -> 运行中
  -> 待复盘
  -> 已复盘
```

- 审批退回会将活动返回“退回修改”。
- 只有完成全部审批的活动可以创建执行批次。
- 只有“待执行”批次可以启动；只有“运行中”或“已暂停”批次可以导入反馈。
- 没有反馈数据时不能生成复盘。

## 3. 主要持久化对象

| 对象 | 用途 |
| --- | --- |
| `campaign_versions` | 冻结提交时的客群规模、产品包、预算、ROI目标、渠道和说明。 |
| `approval_tasks` / `approval_decisions` | 三段审批节点及每次通过或退回决定。 |
| `execution_batches` | 执行渠道、目标人群、启动和完成状态。 |
| `feedback_metrics` | 送达、点击、出票、收入、基准收入和成本。 |
| `campaign_reviews` | 汇总指标、ROI和下一轮建议。 |
| `business_action_events` | 每一次业务动作的操作者、状态变化和上下文，可用于回放。 |

## 4. API 边界

| 动作 | 接口 |
| --- | --- |
| 创建活动 | `POST /api/campaigns` |
| 提交审批 | `POST /api/campaigns/{campaign_id}/submit` |
| 查看 / 处理审批 | `GET /api/approvals`、`POST /api/approvals/{approval_id}/decisions` |
| 创建 / 启动批次 | `POST /api/execution-batches`、`POST /api/execution-batches/{batch_id}/start` |
| 导入反馈 | `POST /api/feedback` |
| 生成复盘 | `POST /api/campaigns/{campaign_id}/reviews` |
| 查询完整闭环 | `GET /api/campaigns/{campaign_id}/lifecycle` |

所有接口均使用当前租户上下文，写入接口需要写权限；审批处理限制为营销经理或租户管理员，合规节点仅允许租户管理员处理。

## 5. 指标口径

```text
增量收入 = 实际收入 - 基准收入
ROI = 增量收入 / 营销成本
点击率 = 点击数 / 送达数
出票转化率 = 出票数 / 送达数
```

营销成本为零或未导入时，ROI 返回空值，页面必须显示“待补充成本”，不得将收入成本比或演示数值表述为增量 ROI。

## 6. 前端演示路径

生产工作台的“营销活动中心”中，打开某一活动的详情即可查看真实活动状态、版本记录、审批链路、执行批次、复盘结果和审计时间线。详情中的可操作按钮随状态变化出现，避免把自然语言提示当作已执行动作。

## 7. 后续开发

1. 接入用户画像、产品、库存和渠道回执的授权接口，替换演示反馈。
2. 为活动配置增加内容版本、频控、预算和事实校验的结构化快照。
3. 将审批角色映射到组织岗位与 OA 工作流。
4. 引入异步任务队列、批次重试和幂等回调处理。
5. 使用对照组或因果归因模型验证增量收入，避免仅以活动收入代表营销效果。
