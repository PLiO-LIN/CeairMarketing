# AI 智能体功能与鲁棒性测试报告 v1.0

## 1. 测试范围

本次测试覆盖营销智能助手、统一 Harness、OpenAI 兼容模型客户端、营销知识检索、本体检索、租户隔离和模型配置边界。测试目标是确认智能体可在东方航空营销业务约束下调用真实数据工具，并在网络抖动、错误配置、非法输入和提示注入场���中保持可诊断、可恢复且不泄露敏感信息。

## 2. 模型接入结论

用户提供的 `agentstudio` 地址不是 OpenAI 接口根路径，直接拼接 `/models` 或 `/chat/completions` 会返回 404。同一服务实例可通过 `/compatible-mode/v1` 提供 OpenAI 兼容接口，平台已按兼容地址配置，模型名称为 `qwen3.8-flash`。API Key 仅以加密密文存储，不写入代码、测试报告或运行日志。

## 4. 真实模型端到端测试

使用平台 `/api/agent-chat` 接口完成一次真实模型低流量测试，问题为上海至三亚航线营销机会分析及人工确认事项。结果如下：

- HTTP 状态：200
- 总耗时：44.32 秒
- 回答长度：950 字符
- 证据来源：1 个去重来源对象
- Harness 轨迹：完成上下文加载、5 次模型调用、4 次结构化决策解析、4 次工具调用和最终综合回答
- 业务门禁：回答保留人工审核要求，没有直接执行活动发布、预算审批或渠道触达
- 敏感信息：响应中未出现模型 API Key 或认证头

该结果说明模型服务、统一 Harness、工具编排和最终综合链路可运行。当前真实调用时延仍较高，主要来自多轮“规划—工具—再规划”循环，而非单次网络重试。

## 5. 本次修复

1. 为聊天生成和模型发现统一加入最多 3 次重试。
2. 对 429、502、503、504 和瞬时连接类异常使用指数退避。
3. 将连接、读取、写入和连接池超时拆分配置，避免单一超时失控。
4. 对非瞬时 4xx 立即失败，避免无效重试和额度浪费。
5. 增加模型响应结构校验，避免第三方异常响应触发未处理的 KeyError。
6. 异常信息统一脱敏，不记录请求头、Key 或第三方原始响应正文。
7. 修复自动化测试修改真实 provider 后不恢复的问题。

## 6. 生产边界与剩余风险

- 查询、分析和生成建议可以由智能体直接执行；活动发布、本体正式更新、预算审批、合规放行和渠道触达必须进入人工确认。
- 当前聊天编排最多进行 4 轮工具决策，复杂问题可能产生约 40 至 90 秒时延。后续应增加工具选择短路、相同查询去重和会话级缓存。
- 本次真实模型测试采用单请求低流量方式，尚未进行并发压测和供应商限流容量测试。
- 证据来源按业务对象去重，因此来源数量不等同于工具调用次数。生产界面应同时展示工具轨迹和具体证据片段。
- 对模型侧 429/5xx 已具备客户端重试，但仍建议在网关层配置熔断、租户级并发上限和调用预算告警。
- 平台操纵应逐步统一为 `executed`、`needs_confirmation`、`forbidden`、`failed` 四类动作结果，不能把自然语言回答视为动作已完成。
