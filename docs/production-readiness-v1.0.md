# 生产上线基线 v1.0

## 已落地的上线护栏

- 生产环境禁止使用 SQLite，必须配置 PostgreSQL。
- 生产环境拒绝默认 `TOKEN_SECRET`、默认管理员密码和空的 `ENCRYPTION_KEY`。
- 生产环境必须配置明确的 `CORS_ORIGINS`，不允许使用 `*`。
- API 响应统一返回 `X-Request-ID`，客户端可透传自己的请求号，便于日志检索。
- 应用启动时记录当前 schema 版本；`/health/ready` 会校验数据库版本是否匹配。
- 数据源配置按租户隔离，仅租户管理员可创建、修改和测试连接。
- 数据处理任务支持取消；失败任务要实现真实重试，前提是原始文件或请求体已持久化到对象存储。

## 发布顺序

1. 备份 PostgreSQL，并确认备份可以恢复。
2. 配置服务器环境变量，不把密钥写入镜像或代码库。
3. 执行数据库 schema 初始化和应用启动检查。
4. 检查 `/health/live` 与 `/health/ready`。
5. 使用只读账号验证登录、租户隔离、知识中心和活动查询。
6. 使用测试租户验证活动审批、执行批次、渠道回执和效果复盘。
7. 再开放真实渠道触达权限。

## 必须完成的外部联调

当前代码提供了接入边界，但以下能力必须由东航现有系统和运维基础设施完成联调，不能用演示数据替代：

- 产品管理平台：产品包、库存、资格、有效期和上下架状态。
- 用户画像平台：画像指标、标签、客群规模、触达许可和保护规则。
- 航班与经营系统：航班计划、客座率、正常率、库存、运价和收入。
- 触达渠道：东航 App、短信、微信、官网、企业客户、OTA、NDC。
- 交易结果：出票、领券、核销、选座、行李、升舱、保险、贵宾室和空铁联运。
- 基础设施：Redis/消息队列、独立 Worker、对象存储、定时调度和告警。

## 当前版本边界

平台已经具备活动主链路和治理基础，可用于内部联调。真实生产上线前仍需完成正式数据库迁移工具、对象存储、持久化任务队列、真实渠道回调、交易归因和智能体评测集。
