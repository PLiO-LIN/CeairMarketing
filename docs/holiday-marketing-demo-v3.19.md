# 东东节假日出行营销演示

## 演示入口

登录 `http://127.0.0.1:8784/`，切换到“竞赛演示（虚构数据）”。首页保持官网式轻量对话；点击“进入智能空间”查看完整过程、历史对话和任务。

推荐提问：

> 请用已导入的数据做 2026 年国庆上海到三亚的家庭出游活动营销，展示图表、本体约束、证据路径与完整过程。

默认窗口为 2026-10-01 至 2026-10-07，画像/业务观测时点为 2026-09-30 23:59:59。窗口是模拟演示口径，日期结束后不会被描述为可直接投放；如需下一节假日，应在卡片中重新选择日期并重算。

## 输出结构

东东公开展示七个阶段：出行窗口、需求与航线、客群资格、航班与本体校验、关系约束与证据、活动方案、效果与复盘。每个阶段可折叠，包含来源、统计口径、通过/排除/待核验状态和相应图表或明细。执行过程只展示公开动作、工具结果和规则检查，不展示模型隐藏思维内容。

可在“出行窗口”选择航线、客群、渠道、产品、日期与预算后重新提问。图谱中的对象可点击查看来源、数据集、记录键和观测属性；“本体关系对照”选择一条关系后，后台会在同一参数下重新计算基线与忽略关系的结果，原始图谱不被修改。缺少 `operates_on`、`uses_product` 或 `includes_ancillary` 时，合格航班、候选产品和活动方案会变为 0/阻断。

点击“保存活动草稿”或继续说“保存当前活动方案为草稿”只创建待确认任务。后台在保存前再次运行客群、航班、产品和预算校验；确认后才写入活动、冻结客群快照、内容草稿和业务本体投影，同时保留 Recommendation→Evidence 和 Recommendation→Campaign 的证据关系，任何渠道触达仍需人工审批。

## 本体的实际作用

本体为 `Flight`、`Route`、`FlightSegment`、`Airport`、`Cabin`、`Fare`、`Product`、`ProductPackage` 和 `AncillaryProduct` 提供统一类型及关系端点校验。场景把画像/事件的需求候选与航班供给、产品有效期、机场适用范围、库存观测和渠道资格组合起来，并为每条路径保留源行证据。

本体不是唯一能实现规则的技术。它的演示价值在于：跨源对象使用同一语义类型；多跳条件可以沿关系传播；关系缺失会触发明确阻断；图谱、方案和证据使用同一对象标识；保存草稿时业务对象和投影关系可以回溯。SQL、规则引擎或代码也能做其中一部分，但需要分别维护连接、语义约束和证据追踪，本体把它们放在一个可复用的约束层。

## 数据与边界

模拟客户、订单、事件、触达、航班、库存和产品目录均带数据集键、数据模式、版本和观测时点。航班阶段还展示同航线同出行日期的爬取报价参考，独立标注为抓取时间未知、待核验，不混入模拟可售库存。爬取数据未提供真实库存、座位数或可靠抓取时间，不能推导历史价格趋势。模拟实验以随机分配 ITT 方式展示评估口径；历史差值不是本活动的效果预测，当前活动 ROI 在执行和成本回收前保持待定。
