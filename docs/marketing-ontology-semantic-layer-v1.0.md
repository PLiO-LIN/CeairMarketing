# 东航智能营销经营本体语义层 v1.0

## 1. 建设定位

本体是东航智能营销活动及服务平台的业务语义和运营底座，不是独立的标签系统，也不是只用于展示的关系图谱。它统一描述市场、航线、航班、客户聚合、客群、产品、内容、活动、审批、执行、反馈和复盘，并为智能体提供稳定的读写契约。

平台页面继续以机会、客群、产品、内容、活动、审批、执行和复盘工作台为主。本体通过后端服务嵌入这些流程，不要求业务人员先理解知识图谱概念才能开展工作。

## 2. 设计原则

1. 本体建模真实航空营销业务对象，不复制源系统表结构。
2. 数据事实、智能体推断、营销建议和人工决策必须区分。
3. 每个对象和关系保留来源、证据、置信度、有效期、版本和租户边界。
4. 智能体只能产生候选事实、推断和建议；正式业务状态由人工动作或受控工作流更新。
5. 标签作为对象的可配置业务属性，不预置具体标签值。
6. 已有用户画像接口标签可直接映射为可配置属性；运营人员可新增、停用或替换属性；历史活动引用不物理删除。
7. 本体对象、关系、动作和函数均需注册后使用，扩展类型保留兼容入口并进入治理清单。

## 3. 营销经营主线

```text
市场、航班、经营、画像和产品数据
                    ↓
数据清洗、实体抽取、关系识别和指标标准化
                    ↓
市场信号、航线、航班、指标和业务证据
                    ↓
营销机会 → 客群快照 → 产品包 → 内容 → 活动版本
                    ↓
多级审批 → 执行批次 → 渠道反馈 → 效果复盘
                    ↓
策略建议 → 人工确认 → 影响下一轮营销经营事项
```

`MarketingCase` 是贯穿上述过程的营销经营事项。一个活动可以有多个版本、审批任务、执行批次和复盘结论，但都能够追溯到同一个经营事项、原始机会及其证据。

## 4. 语义对象

### 数据与航空经营

- `MarketSignal`：舆情、搜索、节假日和市场趋势信号。
- `Market`：国内、国际及地区、区域和目的地市场。
- `Airport`：机场、中转点和地面服务地点。
- `Route`：航线经营对象。
- `Flight`：航班、航段、计划和运行状态。
- `MetricObservation`：客座率、正常率、库存、价格、送达和转化等带时间指标。
- `Evidence`：支撑事实、推断、建议和人工决策的证据。

### 客户与产品

- `CustomerAggregate`：不暴露个人明细的 ToB 或 ToC 客户聚合。
- `AudienceSnapshot`：在指定时间和规则下计算出的活动客群版本。
- `ConfigurableAttribute`：来源于原画像接口、运营配置或智能体建议的可配置属性。
- `Product`：客票、运价、辅营、联运、卡券和会员权益等活动产品。
- `ProductPackage`：供活动引用的产品和权益组合版本。

### 营销活动全生命周期

- `Opportunity`：基于事实和规则识别出的营销机会。
- `MarketingCase`：营销经营事项主线。
- `ContentAsset`：渠道内容及其事实依据和审核状态。
- `Campaign`：营销活动。
- `CampaignVersion`：活动方案版本。
- `ApprovalTask`：营销、预算、产品或合规审批节点。
- `ExecutionBatch`：按客群、渠道和时间窗口形成的执行批次。
- `Channel`：东航 App、微信、短信、官网、企业和分销触点。
- `Feedback`：送达、打开、点击、出票、辅营、退订和投诉反馈。
- `Review`：效果复盘。
- `Recommendation`：等待人工确认的营销建议。
- `HumanDecision`：人工采纳、修改、驳回或审批结果。
- `BusinessRule`：MCT、资格、库存、频控、保护、预算和合规规则。
- `AgentRun`：智能体读取本体、调用函数和生成候选结果的运行记录。

## 5. 标签和画像属性

标签不单独建设为一个一级业务中心，而是作为客群、航线、航班、产品和活动对象的可配置业务属性。

支持三种来源：

1. 复用用户画像或其他系统接口的已有标签。
2. 运营人员按业务需要新增、停用或替换属性。
3. 智能体根据数据提出属性建议，经过人工确认后使用。

本体不预置学生、亲子、价格敏感等具体值。属性值、来源、口径和有效期由实际系统接口和运营配置决定。

## 6. 数据进入本体

### 数据来源

- 市场数据：舆情、搜索热度、目的地趋势和节假日信息。
- 航班数据：航班计划、运行状态、客座率、正常率、库存和中转信息。
- 经营数据：出票、收入、辅营、渠道和历史活动结果。
- 用户画像：会员、出行、搜索、购买、触达和企业差旅聚合信息。
- 产品管理平台：客票、运价、辅营、卡券、权益、产品包和规则。

### 更新过程

```text
连接器接入
  → 格式清洗
  → 字段标准化
  → 实体识别与对齐
  → 指标和关系抽取
  → 数据质量校验
  → 置信度和有效期计算
  → 候选本体事实
  → 自动规则或人工审核
  → 写入正式本体实例
```

智能体不得直接将自然语言结果写成正式事实。所有更新需要保留来源、证据和运行记录。

## 7. 智能域契约

### 机会洞察

读取市场信号、航线、航班、经营指标、历史复盘和业务规则；输出机会、建议和证据；调用机会评分和异常识别函数。

### 客群洞察

读取客户聚合、可配置画像属性、历史反馈和人工决策；输出客群快照、建议和证据；调用客群规模和频控校验函数。

### 产品匹配

读取机会、客群快照、产品、产品包、航班和规则；输出匹配建议和证据；调用产品资格与 MCT 校验函数。

### 活动编排

读取机会、客群、产品包、规则和人工决策；输出营销经营事项、活动、活动版本、执行批次和建议。

### 内容生成

读取客群、产品包、活动版本和规则；输出内容版本、建议和事实证据；调用内容事实校验函数。

### 效果分析

读取活动、执行批次、反馈、指标和人工决策；输出复盘、策略建议和证据；调用活动效果计算和异常识别函数。

## 8. 业务动作和函数

动作表示受权限、状态和审计约束的业务变更，包括确认机会、创建客群快照、确认产品匹配、生成内容草稿、提交审批、审批活动、安排执行、暂停执行、完成复盘和采纳建议。

函数表示可复用的业务计算，包括机会评分、客群规模、产品资格、MCT、触达频控、内容事实、活动效果和异常识别。

动作负责改变业务状态，函数负责计算和校验，智能体负责组合对象、关系和函数生成候选建议。

## 9. 当前接口

- `GET /api/ontology/semantic-model`：返回对象类型、关系类型、动作、函数和智能域契约。
- `GET /api/ontology/status`：返回当前租户实例数据对语义模型的覆盖情况，以及历史或扩展类型清单。
- `GET /api/graph`：返回当前租户本体实例图。
- `GET /api/campaigns/{campaign_id}/graph`：返回指定活动关联的本体实例图。
- `POST /api/imports`：导入符合语义模型的对象和关系实例。

## 10. 后续迭代

1. 数据接入智能体：建立市场、航班、经营、画像和产品平台连接器。
2. 候选事实工作流：增加抽取结果审核、冲突检测和实体对齐。
3. 业务动作服务：将审批、执行、复盘和建议采纳改为受本体约束的动作。
4. 本体查询工具：为六个智能域提供按经营事项、活动版本和证据链查询的工具。
5. 规则服务：将 MCT、资格、频控、保护、预算和合规规则纳入统一调用。
6. 页面嵌入：保持现有工作台结构，仅在业务详情、审批依据和复盘解释中展示本体关系与证据。
